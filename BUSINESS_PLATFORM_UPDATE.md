# MK97 configurable supply chain platform

This code update extends the unified MK97 Operations workspace. It is an overlay for the public project at commit `0741e15e8a1d118c90267fa5800f190b6aa2501c`. It also applies to the previous Unified ERP source ZIP. It has not been deployed.

## Install

1. Back up the current repository and export your organization workspace from **System & Data → Data center & backups**. Keep the existing organization credentials and connector configuration.
2. Copy the ZIP contents to the repository root, preserving all relative paths. The archive contains changed and new files only. `BUSINESS_PLATFORM_CHANGED_FILES.json` lists them.
3. For connected organizations, apply `supabase/migrations/20261104_business_configuration.sql` after the existing unified workspace migrations. The migration adds validation and permission checks for changes to business settings. Existing documents with no business profile remain valid. Static preview and isolated demo mode can run without a database migration.
4. Deploy with the project's existing GitHub Pages workflow. Open **Operations → Business setup**. Confirm the setup in a test workspace first. Verify owner/admin settings, editor access to existing records, and shared sync from a second signed-in device before rolling it out to staff.

## Use the platform

- **Business setup:** Start with all modules, wholesale and distribution, retail and e-commerce, outsourced fulfillment, or industrial supply. Templates populate a draft. Review module choices and rules, set the business name, then save. Shared settings travel with the existing workspace document and backups. Organization owners and admins can save them. Individual terminology, branding and queue perspective remain under **Personal workspace settings**.
- **Operating rules:** Set a default planning horizon, order and hold warning period, dispatch lead time and calendar, minimum safety stock, use of dated unvalidated demand in recommendations, return window, and business time zone. US, Canada and EU can override any rule individually. Suggested ship dates on order details and the dispatch page use the configured calendar. Weekday calendars exclude Saturdays and Sundays; they do not apply holiday calendars. Business setup determines which modules appear in shared navigation. This is not an access-control setting.
- **Stock coverage and purchasing:** Look up a SKU in **Operations → Stock coverage**. The recommendation restores the effective safety buffer after subtracting reservations and damage and adding confirmed, dated inbound. When enabled, unvalidated demand due by the horizon is included separately; it never reserves stock. Discontinued or inactive items are not recommended for purchase. A recommendation opens a prefilled review form. Confirm supplier, receiving location, ETA, quantity, cost, and currency. Saving creates an inventory vendor PO and a scheduled receipt in the existing registers. It does not send email or issue a payment. Changes to the underlying workspace require a fresh review.
- **Customer returns:** Search for an eligible shipped order, choose a SKU and quantity, and authorize the return. One authorization covers one SKU. The quantity limit uses actual shipped units and accounts for prior non-cancelled authorizations. When all authorized units arrive, record restock, quarantine or discard in one inspection. Restock increases usable inventory; quarantine counts as damaged stock; discard adds no inventory. Posting and cancellation are audited, and the open return appears in the Operations work queue. Returns do not issue credits or refunds.
- **Workflow controls:** Switching off new returns or invoice reviews leaves existing records available for completion. The existing customer orders, catalog, suppliers, warehouse, barcode scanning, transportation, 3PL, analytics, tasks, mail and MK Co-Pilot remain in the same workspace.

## Scope and verification

- Configurable for multiple operating models on the existing US/CA/EU workspace structure. This release does not implement manufacturing or MRP, statutory tax, general ledger, automatic refunds, lot or serial tracking for returns, or additional regional workspaces.
- The purchase suggestion is a regional quantity estimate; it is not a time-phased demand forecast or a promise that an order will ship by its requested date. Check the supplier and excluded inbound before ordering.
- Browser preview verified template and regional override persistence, configured shipping dates, PO preparation and creation, return authorization and stock dispositions, and layout at 320, 390 and 768 px. It used isolated fictional records.
- Focused verification: 25 business and Operations tests, 1 PostgreSQL migration integration test, 3 settings tests, and 77 barcode tests. The broader fulfillment suite still has its 9 existing permission and navigation fixture failures. Authenticated production sync and physical devices were not tested.
- Run business and Operations checks: `node --test scripts/check-business-platform.cjs scripts/check-unified-operations.cjs`. The SQL integration test `scripts/check-business-sql.cjs` uses `@electric-sql/pglite`. Settings and scanner UI checks use `jsdom`; scanner core checks use `@zxing/library`. Root and asset mirrors can be checked with `node scripts/verify-mirrors.cjs`.
